## Problem Statements

All three problem statements call for an agent team built on **Crusoe Managed Inference**. Our project's track has not yet been selected.

### Done Means Done

Agents fill in vague goals with their own assumptions, then confidently report success. Build an agent team on Crusoe Managed Inference that writes its own definition of done, checks its work with tests or independent verifier agents, catches itself drifting or looping, and decides whether to continue, re-plan, stop or (rarely) ping a human.

**Core question:** How can agents turn a one-line goal into checks they can run without you, so you can actually walk away?

### Shared Brain

Every new agent on a team starts from zero and pays again for the same context. Build a shared memory layer for an agent team on Crusoe Managed Inference: a living project that every agent reads before it works and updates afterward.

**Core question:** How can a team keep its shared knowledge current, lean and conflict-free while showing measurable gains in output quality?

### Version N+1

Most agent teams are exactly as good on run 100 as on run 1. Build an agent team on Crusoe Managed Inference that improves itself over time: after each run it reviews what worked and what didn't, then rewrites its own prompts, playbooks, tools, or team structure, and keeps a change only if it measurably helps.

**Core question:** How can a team turn its own history into a better version of itself, and prove it with a before-and-after score on tasks it hasn't seen?

## Rules and Eligibility

- **Public repository:** Repositories must be public.
- **Team size:** Maximum of four members; solo participation is permitted.
- **Demo scope:** Highlight only the specific features, code, and functionality the team built during the hackathon. Judges must be able to clearly identify what was created during the event. Failure to clearly identify original contributions results in immediate disqualification.
- **New work only:** Do not present an existing project as new hackathon work. Clearly distinguish the team's contributions; failure to do so results in immediate disqualification.
- **Rights and policies:** Projects are disqualified if they violate legal, ethical, or platform policies, or use code, data, or assets the team does not have rights to use.

## Judging

Judging has two rounds. Each live demo is approximately **three minutes**, followed by **one to two minutes of Q&A**.

### Round One

Teams are assigned to judging groups in different rooms at the venue.

| Criterion | Weight | What judges assess |
| --- | --- | --- |
| Technicality | 40% | Difficulty to recreate, technical depth beyond an average hackathon project, and what was built in the available time |
| Live demo | 20% | An impressive, well-engineered, working demonstration |
| Creativity and originality | 25% | A creative project judges have not seen before |
| Future potential and AI impact | 15% | An interesting future for AI; advances in capabilities, autonomy, learning, evaluation, or agentic systems |

### Round Two

The **top six teams** demo on stage before a panel of judges and all attendees. The same four criteria apply with **equal weighting: 25% each**.
